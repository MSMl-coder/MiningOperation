# Mining Operation — Environment Generator v2.3.2

Невелике стабілізаційне оновлення над **v2.3.1**. Не перегенеровує поле автоматично й не змінює ID, мінеральний склад, геометрію або збережені запаси астероїдів.

## Встановлення

1. В Unity закрий **Asteroid Field Studio**, вийди з Play Mode й збережи копію проєкту або створи Git-коміт.
2. Відкрий `MiningOperation_Asteroids_v2.3.2_PATCH.zip`.
3. **Вміст** папки `MiningOperation_Asteroids/` із архіву перенеси до `Assets/_MiningOperation/Game/Asteroids/`, замінивши однойменні файли. Не створюй вкладену папку `MiningOperation_Asteroids` усередині чинного `Asteroids`.
4. **Збережи існуючі `.meta`** старих файлів, аби не втратити GUID. Для нового тесту Unity створить `.meta` автоматично.
5. В Unity дочекайся перекомпіляції. Перейди в **Tools → Mining Operation → Asteroid Field Studio**.
6. У `VISUALS` для Gas/Ice натисни `Install / Repair Ice & Gas Assets` тільки якщо матеріали не встановлені чи не працюють. Вручну призначені справні матеріали більше не перезаписуються.
7. Перевір EditMode тести через Test Runner.

## Єдине вікно

- `LOCATION`: вибір `Rock / Ice / Gas`, seed, ID, розподіл хмар/астероїдів, ресурсні характеристики; ліворуч — перелік Spawn Point.
- `SHAPE & QUALITY`: геометрія та LOD для Rock/Ice. Для Gas показано лише пояснення, оскільки газ не використовує астероїдні меші.
- `VISUALS`: лише налаштування поточного типу, без зайвих параметрів чужих систем.
- `PREVIEW`: 2D-розташування, зразок Rock/Ice, контроль застарілого перегляду.
- Внизу: чіткий статус (`NOT BUILT`, `CHANGES NOT BUILT`, `UP TO DATE`) і одна команда Build.

## Газ: не переплутати дві операції

**Зовнішній вигляд** (`Opacity`, `Puffs per cluster`, кольори, матеріал): змінюй у `VISUALS`, потім натисни **Apply Appearance (preserve gas mass)**. Ресурсні записи, кількість добутого газу та координати хмар зберігаються.

**Ігрові дані** (seed, Field ID, кількість/розмір/розподіл хмар, загальна маса, газовий ресурс): після зміни статус покаже `GAS CHANGES NOT BUILT`; `BUILD / REBUILD` створює новий запис хмар. Якщо газ уже частково видобуто, редактор запросить підтвердження, оскільки це скидає прогрес конкретного газового поля.

Сумарна маса **нових** газових родовищ тепер дорівнює заданому `Initial gas mass (kg)` (раніше випадкові множники її зміщували). Візуальна насиченість хмари поступово слабшає при вичерпанні газу. Оновлення частинок обмежене інтервалом приблизно 0,5 с, щоб не перебудовувати Particle System на кожен виклик видобутку.

## Сумісність

- Rock/Ice: формат і дані астероїдів не змінювалися.
- Gas: додано **необов'язкове** JSON-поле `authoringSignature`; старі записи без нього завантажуються і відображаються як `GAS BUILT · LEGACY SETTINGS`, **без автоматичного видалення або перегенерації**.
- Старі значення `initialMassKg` не нормалізуються заднім числом: збережені маси залишаються такими, якими їх було записано.
- `SyncVisualVisibility()` приховує газову систему частинок після перемикання Spawn Point на Rock/Ice, не видаляючи сам газовий snapshot.
- Встановлення візуальних assets тепер не скидає відредаговані вручну справні матеріали; текстури повторно імпортуються лише за потреби.

## Межі перевірки

ZIP, структура скриптів і статична цілісність були перевірені. **Компіляція в Unity 6, фактичне виконання EditMode-тестів і FPS у цьому середовищі недоступні**. Якщо Unity покаже помилку компіляції, надішли перший запис із Console з файлом і номером рядка.

Газ залишається спрайтовим Particle System, а не raymarched volumetric cloud. Повноцінне об'ємне освітлення й 3D-взаємодія потребують окремого графічного етапу.
