# Аудит Mining Operation — Asteroid Generator v1.0 → v1.1

## На чому ґрунтується аудит

Оглянуті фактичні файли v1.0: `AsteroidDefinitions.cs`, `AsteroidGeneration.cs`, `AsteroidGeometryGenerator.cs`, `AsteroidInstance.cs`, `AsteroidSaveUtility.cs`, `AsteroidGeneratorStudio.cs`, `AsteroidRandom.cs`, EditMode tests та `.asmdef`.

## Виявлені проблеми та зміни

| Питання v1.0 | Наслідок | Стан v1.1 |
|---|---|---|
| `rareChance...` лише множили ваги | Значення 0.25 не дорівнювало 25% | Реальні пер-астероїдні Bernoulli gates + тести граничних 0/1 |
| Неконтрольовані масові частки після вибору ресурсів | Висока частка надрідкісних матеріалів | Кепи часток Rare/Exotic; обов'язкова базова складова |
| Арифметична середня густина за масовими частками | Неточні маси змішаного матеріалу | Гармонійне середнє + пористість |
| Форма відтворювалася з *поточних* settings | Зміна assets змінювала старі астероїди | `AsteroidGeometryProfile` в даних v2 |
| Об'єм від LOD0 | Масу змінювало редагування графічного LOD | Окремий `volumeSubdivisions` |
| Регулярне перестворення ікосфери для кожного LOD | Зайва робота під час генерації | Кеш шаблонів топології v2 |
| LOD дочірні об'єкти і meshes могли втрачатися під час domain reload | Некоректні рендери/ресурсні витоки | Явне rebuild при Play, перевірка втрати посилань в Edit Mode, ownership тимчасових meshes |
| Editor дублював один seed/ID при багаторазовому створенні | Конфлікт у збереженні | Автоматичні суфікси ID для додаткових сценових екземплярів |
| Відновлення довіряло входу | Пошкоджені маси та частки могли потрапити в state | Перевірки schema/version, numeric values, fraction sum, duplicate IDs |
| Невелике покриття тестами | Непомічені граничні сценарії | Нові тести класів, LOD, густини, збереження, видобутку, ID |
| Рандомізація геометрії мала обмежені сімейства силуетів | Одноманітність великих наборів | Додані режими пропорцій, контактові форми, площини розлому |
| Preview використовував editor builtin material | Можливий некоректний вигляд у URP | URP/Standard material fallback та asset при створенні налаштувань |

## Сумісність

JSON схеми 1 підтримується, геометрію V1 реалізовано окремим `AsteroidGeometryLegacyV1` без зміни її математичних формул. Для V1 точність повтору залежить від **незмінених старих Generator Settings**, оскільки попередній формат не містив shape snapshot.

Для v2 збережено shape snapshot, але не snapshot каталогів (composition і густина уже збережені чисельно). Якщо існуючий каталог видалити/змінити ID, стара composition продовжить зберігатися в даних, однак сумісність із зовнішнім інвентарем/економікою треба підтримувати окремо.

## Невирішені production-задачі

- Великий астероїдний пояс потребує Field Manager зі streaming, pool та рознесенням генерації на кадри.
- Генерація високодетальних мешів і MeshCollider — основний CPU bottleneck, особливо на мобільному пристрої чи при створенні сотень тіл одночасно.
- Статистика рідкісності коректна за налаштувань достатньої кількості слотів; при занадто малому `maximumResources` одночасні Rare/Exotic не можуть гарантовано поміститися.
- Повноцінна міграція геометрії V1 на нову форму автоматично неможлива без втрати старого силуету; тому V1 режим залишається окремим.
- Серіалізація `Data` не включає обертання, місце розташування, інвентар колекторів, рух, квести — ці поля належать майбутньому World/Field Save Manager.
- Жодного запуску Unity Test Runner або профілювання у Unity 6 у цьому середовищі не виконано.

## Перед прийняттям у репозиторій

1. Імпортувати поверх v1.0, не видаливши чинних Unity `.meta` скриптів.
2. Запустити EditMode Test Runner, перевірити Console (0 Errors).
3. Створити декілька тіл одного seed у Studio і перевірити різні ID у Scene.
4. Зберегти сцену, перезапустити Unity і перевірити меші та LOD.
5. Згенерувати AST I/II/III і перевірити дані та фактичний вихід `ExtractResources`.
6. Зберегти/відновити JSON v2, перевірити, що поточна маса не перераховується.
7. Прочитати v1 save зі старими налаштуваннями й перевірити старий silhouette.
8. Зробити performance test при 50–200 астероїдах, за можливості створювати поступово.
