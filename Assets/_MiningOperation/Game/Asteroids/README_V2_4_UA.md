# Mining Operation — Environment Generator v2.4

## Що нового

Версія 2.4 додає **необов’язкову об’ємну візуалізацію газових хмар**. Кам’яні й льодові астероїди, ID, ресурсні класи, їхні сейви й формації залишаються без змін.

- `Volumetric`: один об’єкт `MO Gas Volume` на всю газову локацію, один об’єднаний процедурний mesh для всіх її хмар (до 20) і URP-шейдер, який обчислює **3D-щільність** усередині об’ємів (raymarching). Тривимірний шум не використовує тайлінг 2D-текстури.
- `SoftParticles`: існуючий надійний режим частинок. У старих сценах він залишається активним за замовчуванням.
- Якщо shader `MiningOperation/GasVolumeURP` відсутній, скомпілювався з помилкою чи не підтримується рушієм, Runtime повертається до `SoftParticles`, замість того щоб показувати рожевий матеріал.
- Освітлення: напрямок і колір використовуються з `RenderSettings.sun` (якщо заданий), інакше застосовується нейтральне стилізоване освітлення. Це **не фізично точна** модель розсіювання світла.
- Роздільне налаштування якості, кольорів, прозорості, повільного руху й дистанції відображення. При зміні цих параметрів **не змінюються** ID, seed або положення хмар.
- Жодних запасів газу й жодного видобутку: газ може вироблятися **лише майбутньою промисловою системою**, не цим модулем.

## Встановлення на v2.3.3

1. Зробіть коміт/резервну копію Unity-проєкту. Вийдіть із Play Mode.
2. Розпакуйте PATCH. Скопіюйте **вміст** `MiningOperation_Asteroids/` до `Assets/_MiningOperation/Game/Asteroids/`. Замініть наявні `.cs`, але **залиште їхні старі `.meta`**. Для нових `.cs` і `.shader` Unity створить `.meta` автоматично.
3. Дочекайтесь завершення імпорту і перевірте Console. В Unity має бути активний **URP Asset**. Якщо шейдер не компілюється, залишайтесь у `SoftParticles` і надішліть першу помилку з Console.
4. Відкрийте **Tools → Mining Operation → Asteroid Field Studio**. Оберіть газову точку спавну та вкладку **VISUALS**.
5. Натисніть **Install / Repair Ice & Gas Assets**. Ця дія створить `MO_GasVolumeURP_v24.mat`, якщо шейдер доступний, **не замінюючи** ваші справні користувацькі матеріали.
6. Змініть **Rendering mode → Volumetric**; спочатку **Raymarch samples = 8–10**, **3D noise scale = 1**, **Opacity = 0.18**. Натисніть **Apply Cloud Appearance**. Якщо ще немає збереженої газової формації, натисніть **BUILD CLOUD VISUALS** внизу вікна.
7. Перегляньте результат у **Game View** і **Unity Profiler** (особливо GPU). Для швидкого повернення до старої стабільної системи виберіть `SoftParticles` і `Apply Cloud Appearance`.

Нові газові Spawn Points, створені через Field Studio v2.4, починають з `Volumetric`. Старі залишаються на `SoftParticles` до ручного перемикання.

## Параметри газу у VISUALS

| Параметр | Старт | Призначення |
|---|---:|---|
| Rendering mode | Volumetric | Нові газові точки; старі — SoftParticles |
| Raymarch samples | 10 | Якість/вартість GPU, 6–24 |
| 3D noise scale | 1.0 | Масштаб нерівностей всередині хмари |
| Brightness | 1.0 | Яскравість псевдооб’ємного світла |
| Visibility range (m) | 14 000 | Дальність ввімкнення рендера від камери (з урахуванням радіуса хмари) |
| Opacity | 0.18 | Оптична щільність |
| Layer irregularity | 0.35 | Сила деформації силуету/внутрішньої неоднорідності |
| Gentle drift | 0.32 | Повільний рух візерунка (або шум частинок у резервному режимі) |

**Важливо щодо продуктивності:** при великих хмарах, що заповнюють екран, raymarching обчислюється на кожному пікселі видимого об’єму. Зменшіть кількість samples до 6–8 та кількість/розміри хмар, якщо GPU час кадру збільшується. Об’ємний режим — опціональний: підтримка й продуктивність у Unity 6/Metal ще не підтверджені тестом у редакторі.

## Сумісність і обмеження

- JSON газових хмар лишився `schemaVersion = 2`, формат не змінювався. Старі v2.3.x газові записи читаються за попередніми правилами.
- Параметри зовнішнього вигляду **не входять** в `authoringSignature`; `Apply Cloud Appearance` не перегенеровує структуру хмар.
- Кам’яні/льодові поля, ID, класи I–III й стан видобутку не змінюються.
- У новому режимі геометрія — об’єднані оболонки газових об’ємів. Це не повна симуляція газової динаміки, він не відкидає фізично точні тіні й не відстежує затемнення об’єктами, що перебувають всередині хмари. Для цього знадобиться окремий URP Render Feature з коректною обробкою scene depth.
- Для сцен, де задано не `RenderSettings.sun`, використовується нейтральний напрямок освітлення; якщо змінити сонце після натискання `Apply`, повторно застосуйте appearance.
- Прев’ю, створене в редакторі, генерує тимчасовий (не серіалізований у scene asset) візуальний mesh, який Runtime відтворить на старті Play Mode. Після перезапуску Unity потрібно натиснути `Apply Cloud Appearance`, щоб відновити **Editor preview**.

## Що перевірити після оновлення

- [ ] Rock/Ice Spawn Points як і раніше працюють.
- [ ] Зміна Gas у `SoftParticles` прибирає об’ємний меш і показує старі частинки.
- [ ] Зміна Gas у `Volumetric` створює лише `MO Gas Volume`, не створює GameObject на кожну хмару.
- [ ] При русі камери всередину хмари не з’являється суцільна куля або маджента.
- [ ] У збільшенні на краях немає UV-швів чи повторення плиток.
- [ ] Зміна opacity/brightness не змінює `authoringSignature` або `CaptureJson()`.
- [ ] При переміщенні далеко від хмари renderer вимикається.
- [ ] Порівняйте час GPU кадру в обох режимах у Profiler.

## Статус перевірки

Пакет перевірено статично та на цілісність ZIP, вміст зіставлено з v2.3.3. C# і HLSL **не проходили фактичної компіляції в Unity 6/Metal**, а GPU performance не вимірювався. Це інтеграційна збірка для тестування у вашому Unity-проєкті.
